Intent parameters

The parameters sent with a call are built in three layers. A key in a later layer replaces the same key from an earlier one:

  1. Set by Jane — values the protocol generates (nonces) or copies from the selected element.
  2. The intent — the parameters stored with the intent you selected.
  3. This page — whatever you type in Intent Parameters.

The merged set is recorded in the claim as its call parameters, so you can always see what was actually sent. Which keys mean anything depends on the protocol of the endpoint you selected and the function of the intent.

Set by column:
  • JANE generated on every call
  • ELEMENT copied from the element
  • INTENT normally stored in the intent
  • YOU supply it here
Anything set by Jane or the element can still be overridden from this page.

Test protocols — A10NULLPROTOCOL, A10NETCONF, TESTCONTAINERPROTOCOL, EVCLI_PSA

These return fixed test claims and ignore all intent parameters. Each records its own random 32-byte nonce in the claim. A10NULLPROTOCOL and A10NETCONF only produce a non-error claim for function null/null; EVCLI_PSA only for veraison/psa/get_token.

Rules and rule parameters

Each selected rule is run against the claim just collected, and the Rule Parameters object is given to every one of them. Rules are ignored when Attest Only is chosen.

Most rules take no rule parameters: they read what they need from the claim, from the element, or from an expected value. Only the Keylime rules use rule parameters.

Before you verify:
  • Pick rules that match the intent's function; a TPM rule run on a sys/info claim will not pass.
  • A rule marked EV needs an expected value for this element, endpoint and intent, or the result is missing expected value.
  • Running any rule on an error claim gives verify claim error attempt.
